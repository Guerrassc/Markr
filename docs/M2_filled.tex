\section{Experiment and results}
The script compares regex, small-LLM and large-LLM extraction on 10 synthetic briefs (essay, lab, Haskell, presentation, reflection, French, rubric, email, problem set, thesis). Metric: requirement recall; a labelled requirement counts when one extracted line contains all annotated key strings. Run: \texttt{python experiments/m2\_extraction/run\_experiment.py}; instructions and raw JSON are in the repository.

\textbf{Results.} Regex: 50.3\% mean recall, 10/10 cases, 3.7 items/brief. Small LLM: 100\% recall on 3/10 completed cases (20 labelled requirements), 10.7 items/brief, 31.49 s median / 186.34 s worst. On those same three cases, regex averaged 45.3\%. Seven LLM calls did not complete; large model was not run. Example regex misses (essay): PDF format, Harvard referencing, six-source minimum, title page and late penalty. Evidence is preliminary: synthetic briefs, small sample, imperfect keyword scoring.
\section{Chosen approach, limitations and switch trigger}
\textbf{Choice:} provisionally use \texttt{gemini-3.5-flash-lite}: full recall on the 3 completed cases and lower estimated cost than the larger candidate. Not conclusive: only 3/10 calls completed and worst latency exceeded 3 minutes. \textbf{Limitations:} (1) synthetic briefs and imperfect keyword metric; (2) free-tier availability/latency; (3) student brief/draft data leaves Markr, so check provider terms, retention and consent before real use. Scanned-PDF OCR is untested. \textbf{Switch if:} recall below 90\% on at least 20 varied cases, over 10\% failures after retries, unacceptable latency, or unsuitable privacy terms. Evaluate a paid tier, alternative provider or local model; the large model has not been shown to perform better.
\section{First architecture sketch}
Student + brief/draft $\rightarrow$ Markr UI/backend (PDF text extraction; prompt in \texttt{prompts/}) $\rightarrow$ \textbf{Google Gemini API, \texttt{gemini-3.5-flash-lite}} $\rightarrow$ editable checklist $\rightarrow$ draft comparison $\rightarrow$ met/missing/uncertain results. Brief/draft text leaves Markr for Google. API key is stored in local git-ignored \texttt{.env}; only placeholders are committed. This is the M2 proposal, not a claim that the complete product exists.
\section{First cost estimate}
Google Gemini API paid-tier price assumptions recorded 19 Oct 2026: \texttt{gemini-3.5-flash-lite} \$0.30/1M input, \$2.50/1M output; \texttt{gemini-3.8-flash} \$0.75/1M input, \$3.75/1M output. Source: \url{https://ai.google.dev/gemini-api/docs/pricing}; verify current price/model availability before deployment. Small-model experiment total: 591 input / 430 output tokens across 3 successful calls = about 197 / 143 per extraction; measured extraction cost is $(197\times0.30+143\times2.50)/10^6=\$0.00042$ per brief.

End-to-end estimate (not measured): 3,800 input + 850 output tokens per brief-and-draft action. Small: $\$0.00327/action$, or $\$9.80/month$ at 3,000 actions. Large: $\$0.00604/action$, or $\$18.11/month$. Excludes hosting/storage/tax; development calls used free tier.
